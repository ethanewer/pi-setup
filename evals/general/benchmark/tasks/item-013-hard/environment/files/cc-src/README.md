# cc-src — staged "certified C0" toolchain build (hardened)

This tree is the source snapshot of a staged, CompCert-3.13.1-style **certified
C** front-end build named **c0**. It is deliberately shipped **unbuilt and
defective**, with several problems planted in it. Your job is to bring the staged
build up, clear each planted problem, and end with a working `build/c0` plus the
staged sub-artifacts.

## Layout

```
cc-src/
  configure          autoconf-style bootstrap; must run first
  Makefile           staged build chain
  cert/cert.v        Coq certificate unit (verify stage)
  src/stamp.ml        OCaml module (oextract stage)
  src/ccomp.c        the c0 backend; a header comment documents its language
  probe/sample.c     a sample program
  probe/sample.out   expected output for the sample
  build/machine.h    STALE shipped header - NOT authoritative (see below)
  build/             generated here
```

## Planted problems you must clear

1. **Missing host toolchain.** The image ships only `gcc` and `make`; `configure`
   also needs `ocamlc` (package `ocaml`) and `coqc` (package `coq`). Install
   whatever it reports missing, e.g. `apt-get install -y ocaml coq`.
2. **A benign source defect.** Under the backend flags (`-Wall -Werror`), the
   shipped `src/ccomp.c` does not compile. The compiler names the offending
   line. Remove just that benign line; keep the documented edit boundary exact.
3. **Stale deployment header.** `build/machine.h` ships with `C0_WORDSIZE 32`.
   It is a leftover and is NOT authoritative. Only the `build/machine.h`
   regenerated by `configure` (which derives the wordsize from the real host,
   i.e. **64** on supported x64 hosts) is valid.

## Required steps

```
cd /app/cc-src
./configure          # stage load: probe + write build/machine.h and build/cfg.mk
make verify          # coqc  cert/cert.v                -> build/cert.checked
make oextract        # ocamlc  src/stamp.ml             -> build/oextract.checked
make backend         # gcc -Wall -Werror -Ibuild        -> build/c0
```

or simply `make all` (which runs the stages in that order).

## The c0 CLI

`build/c0` reads a source file and writes a text output file:

```
./build/c0 <input-file> <output-file>
```

Output line 1 is always the deployment header `; wordsize <N>`, where `N` is the
valid configured wordsize (64). After it, for each `put E;` statement in the
input, in order, one line holds the decimal value of expression `E`. The exact
grammar, value semantics, and the permitted edit boundary are documented in the
header comment at the top of `src/ccomp.c`.

## Self-check (required before finishing)

```
./build/c0 probe/sample.c /tmp/probe.actual
diff -u /tmp/probe.actual probe/sample.out
```

A clean diff confirms the header wordsize and backend semantics. Do not delete
`build/cert.checked`, `build/oextract.checked`, or rename anything.
