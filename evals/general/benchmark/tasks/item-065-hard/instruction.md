# Item-065 (hard) — C4-shard packer with exclusion, determinism and deep round trips

The **hard** escalation of the shard-bundle tool.  The corpus (`/app/source`,
generated by `/app/make_tree2.py`) is a larger, deeper, adversarial tree: five
levels of nesting, near-empty and empty directories at every depth, dotted and
space-containing names, a dash-prefixed filename, UTF-8 text, and binary
blobs.  Beyond the medium contract you must also implement **file exclusion**,
**deterministic packing**, and prove the reversible invariants hold through an
exact round trip **before** tuning speed.

## Files in /app

- `/app/source/` — the corpus tree (built by `make_tree2.py`; do not modify).
- `/app/make_tree2.py` — deterministic tree generator (verifier rebuilds the
  expected input from it).
- `/app/c4shards.py` — CLI scaffold with command `pack` / `unpack`.
  Implement the bodies.  **Stdlib only** (`os`, `gzip`, `json`, `base64`,
  `argparse`, `fnmatch`, ...).  `python-chess`-style shortcuts are irrelevant here.

## Contract (same bundle format as the medium task)

`pack(root, bundle_out, limit=4096, exclude=None)` writes a bundle dir:
- `meta.json` — JSON manifest listing the shard filenames (+ record count).
- `shard-*.jsonl.gz` — gzip JSON-Lines; one JSON document per node:
  - `{"type":"dir","path":...}`,  `{"type":"file","path":...,"text":...}`,
  - `{"type":"blob","path":...,"base64":...}` for non-UTF-8/binary content.
  Note that `"file"` records hold **text decoded as UTF-8**; anything else —
  including UTF-8 text containing a NUL byte or any binary — must go through
  `"blob"`/base64 so every byte survives.

`unpack(bundle_in, dest)` recreates all recorded dirs (empty ones included) and
all files byte-for-byte.

## Additional hard requirements

1. **Exclusion.**  `--exclude GLOB` (repeatable) drops any *file* whose
   relative path matches the glob (use `fnmatch.fnmatch`; apply to the
   slash-separated relative path).  Directories are always recorded.  Unpacking
   an excluded bundle must reconstruct the tree with those files simply absent.

2. **Determinism.**  Packing the *same* tree twice must produce byte-identical
   shards and an identical `meta.json` (same record order, same shard split).
   The verifier packs the reference tree twice and compares the shard bytes.

3. **Exact reversible invariants.**  Define (and then verify) the invariant set
   explicitly: identical set of relative paths (dirs *and* files), identical
   file bytes, empty dirs preserved, now with excludes applied.  Write a
   round-trip self-test (`pack` → `unpack` → compare) **before** optimising.

4. **CLI argument handling.**  The CLI must accept both positional output
   destinations and flags in both orders, e.g.
   `pack --exclude '*.bin' src out --limit 64` must behave exactly as
   `pack src out --limit 64 --exclude '*.bin'`.

## Deliverables

- `/app/c4shards.py` — implemented.
- `/app/bundle_shards/` — bundle produced by **your** `pack` of `/app/source`
  (with `--limit` chosen so there are **at least four** gzip shard files).

The verifier: (a) rebuilds the expected tree with `make_tree2.py`; (b) packs it
with your CLI (including `--exclude '*.bin'`) and unpacks, comparing
byte-for-byte against the expected tree *minus* excluded files; (c) unpacks
your shipped `/app/bundle_shards/` and compares to the full expected tree; (d)
packs the reference tree twice and requires identical shard bytes; (e) requires
≥ 4 gzip shards in `/app/bundle_shards/`.  Full pass → reward 1.
