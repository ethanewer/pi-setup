# cistern-buoy: an extreme max-age HSTS header destroys the on-disk HSTS cache

Environment notes for the trial image (also printed in `/app/instruction.md`).

- `/app/src` — a real upstream `curl/curl` source tree, pinned to a single
  snapshot: a shallow, detached clone with exactly one commit. That commit is
  the latest upstream revision at which the defect described in the
  instruction still exists. There is no history to consult and nothing to
  fetch. The tree is fully writable and buildable.
- `/app/src/src/curl` — the built `curl` command-line binary (a **debug**
  build matching the upstream developer setup; the debug build is what makes
  the reproducer in the instruction work at all).
- `/app/src/tests` — the project's own test suite and test harness, built
  (test servers, libtest tools, unit bundles). Run it with
  `./runtests.pl -n <test-selection>` from `/app/src/tests`.
- `make -C /app/src` — incremental rebuild (fast: only changed files
  recompile).
- Toolchain: gcc, autoconf/automake/libtool, openssl dev headers, perl,
  `gdb`, `strace`, python3.
- There is **no network** in this container. Everything needed is on disk;
  do not try to download anything.

The HSTS cache file written by curl looks like this:

```
# Your HSTS cache. https://curl.se/docs/hsts.html
# This file was generated by libcurl! Edit at your own risk.
somehere.example "20330525 03:33:20"
elsewhere.example.com "20330727 03:33:20"
```

One line per remembered host: `[.]hostname "YYYYMMDD HH:MM:SS"`, where a
leading `.` means the policy applies to all subdomains. A host whose policy
never expires is stored as `host "unlimited"`.
