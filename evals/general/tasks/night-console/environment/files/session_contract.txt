# Session protocol (line-oriented)

A session advances through three states: EMPTY (nothing opened),
OPEN (a session is live), and CLOSED (after CLOSE).

Commands (one per input line):
  OPEN <name>                     begin a session   (valid only in EMPTY)
  PUT <key> <value>               store a key/value pair  (valid only in OPEN)
  GET <key>                       retrieve a stored value (valid only in OPEN)
  LIST                            list stored keys, sorted   (valid only in OPEN)
  CLOSE                           end the current session    (valid only in OPEN)

Responses (one per input command):
  OK
  VALUE <value>
  KEYS k1,k2,...                  comma-separated, lexicographic; "KEYS" if empty
  CLOSED
  ERROR not open                  a recognised command while not in an open session
  ERROR open                      OPEN given while already open
  ERROR missing                   GET for a key that is not stored
  ERROR bad                       a known command with missing/invalid tokens
  ERROR unknown                   an unrecognised command name (checked first)

Precedence: the command name is matched before the state. If the first token is
not one of OPEN, PUT, GET, LIST, CLOSE, respond "ERROR unknown" in any state
(EMPTY, OPEN, or CLOSED); the state does not change. The state rules below then
apply only to recognised commands: in EMPTY or CLOSED, a recognised command
responds "ERROR not open". In particular, a CLOSE while EMPTY fails with
"ERROR not open" and does NOT move the session to CLOSED; a later OPEN still
succeeds. A session closed by a successful CLOSE rejects every later recognised
command with "ERROR not open" until the process ends (unrecognised names still
respond "ERROR unknown").

Blank lines are ignored (no output).
Commands are case-sensitive.
