# Harbor Gasket — maritime analytics environment provisioning

**Harbor Gasket Maritime Analytics** runs a CPU-only tidal-research cluster.
You must provision a complete Python 3.12 research environment at `/app/venv`
that (a) installs the shipped scientific framework **swellkit** from its source
tree, (b) pins an exact toolchain (Node.js `v20.19.3`) plus the
`hydra-submitit-launcher` plugin, (c) makes two deep-learning frameworks
(**torch** and **onnxruntime**) coexist with **CPU-only** bindings and no
toolkit clash, and (d) stands up a local package-index server that serves the
built framework to clients.

Read the whole contract before you start. All paths are literal.

## Shipped inputs (never hand-written, never edit)

| Path | What it is |
|------|------------|
| `/app/src/` | the `swellkit` 2.4.1 **source tree** (pure Python + one C extension `swellkit._core`). Build from it; do **not** edit any file under `/app/src/`. |
| `/app/releases/node-v20.19.3-linux-x64.tar.xz` | the **pinned toolchain release artifact** (Node.js v20.19.3, linux x64). It is the exact release you must provision; do not fetch any other version. |
| `/app/kit/import_check.py` | a deterministic import/health check you must **run** (see Task 1). Do not edit. |
| `/app/data/constituents.csv` | sample tide-constituent table used by the health check. Do not edit. |

No GPU is available; the environment must stay **CPU-only end to end** (the
verifier rejects any installed CUDA/NVIDIA binding package).

## Deliverables you must produce

| Path | What it is |
|------|------------|
| `/app/venv` | Python virtual environment you create; contains swellkit (its package installed at `/app/venv/lib/python3.12/site-packages/swellkit`), torch (CPU), onnxruntime, and the hydra plugin, all installed by you. |
| `/app/import-check.txt` | stdout of `/app/venv/bin/python /app/kit/import_check.py`. |
| `/app/pin-toolchain.sh` | **executable**, idempotent, re-runnable toolchain provisioner (Task 2). |
| `/app/toolchain/version.txt` | exact-version report produced by `pin-toolchain.sh` (see format below). |
| `/app/dl-coexist.py` | **executable**, re-runnable CPU-coexistence checker (Task 3) producing `frameworks-ok.txt`. |
| `/app/frameworks-ok.txt` | output written by a run of `/app/dl-coexist.py`. |
| `/app/serve-index.sh` | **executable**, idempotent package-index launcher (Task 4). |
| `/app/package-dir/index.html` | PEP-503-style package index root generated by `serve-index.sh`. |
| `/app/client-install.log` | log proving a client installed the served artifact from the live index (Task 4). |

## Task 1 — install the scientific framework into the venv from source

Create the venv and build swellkit **from `/app/src`**:

```
python3 -m venv /app/venv
/app/venv/bin/pip install --no-cache-dir /app/src
```

swellkit ships a compiled C extension, so this really must build from source
(the image has `build-essential`). Confirm the framework and its helpers are
functional:

```
/app/venv/bin/python /app/kit/import_check.py > /app/import-check.txt
```

The framework's public API (this is the exact behaviour the verifier checks):

- `swellkit.height_hours(t_hours, text)` — harmonic forecast
  `h(t) = sum A*cos(2*pi*t/T + P*pi/180)`. **Edge behaviour (contractual):**
  blank lines and `#`-comment lines are skipped; a row that is not exactly
  four comma-separated fields, that has a non-numeric field, or whose period is
  **not strictly > 0** must **raise `ValueError`**; an empty/comment-only table
  forecasts exactly `0.0`; `t_hours` may be negative or fractional; zero
  amplitude and phase `180` are legal.
- `swellkit.forecast_file(path, t_hours=0.0)` — same, reading the table file.
- `swellkit.rms_amplitude(series)` / `swellkit._core.rms(seq)` —
  root-mean-square computed in the **compiled C core**; **empty sequence → `0.0`**;
  works for single/negative/zero-valued series.
- `swellkit.mean_slice(series, start, stop)` — empty slice → `0.0`.
- `swellkit.haversine_km(lon1, lat1, lon2, lat2)` — zero-distance point pair → `0.0`.
- CLI: `python -m swellkit.tide <file> [<hour>]` prints `%.10f`.

`/app/import-check.txt` must byte-match a fresh re-run of the command above; it
is deterministic (no timestamps). The hidden framework tests **rebuild** swellkit
from `/app/src` in a fresh venv and drive the same public API on edge inputs —
an edited source tree or a skipped C build fails them.

## Task 2 — pin the exact toolchain + runtime plugin

Make `/app/pin-toolchain.sh` (executable) do **all** of the following,
idempotently (a clean re-run must succeed, and wiping `/app/toolchain` then
re-running must succeed):

1. Extract the shipped release artifact to `/app/toolchain/`:
   `tar -xJf /app/releases/node-v20.19.3-linux-x64.tar.xz -C /app/toolchain`
   (only if the `node-v20.19.3-linux-x64` directory is not already present),
   so the interpreter ends up at
   `/app/toolchain/node-v20.19.3-linux-x64/bin/node`.
2. Install the pinned runtime plugin into the venv:
   `/app/venv/bin/pip install --no-cache-dir "hydra-submitit-launcher==1.2.0"`
   (idempotent for the already-satisfied metadata).
3. Write `/app/toolchain/version.txt` with **exactly** these two lines (no
   trailing blank line):

   ```
   node=v20.19.3
   plugin=hydra-submitit-launcher==1.2.0
   ```

   The `node=` value must equal the live `node --version` output
   (`v20.19.3`).

The verifier wipes `/app/toolchain`, re-runs your script, then asserts the live
reports: `<node-dir>/bin/node --version` prints `v20.19.3`, `pip show
hydra-submitit-launcher` in `/app/venv` reports `Version: 1.2.0`, the plugin is
importable (`import hydra_plugins.hydra_submitit_launcher`), and `version.txt`
matches exactly.

## Task 3 — make two deep-learning frameworks coexist on CPU

The cluster runs **torch** and **onnxruntime** together, CPU-only. The default
PyPI mirror's `torch` wheels now drag in dozens of `nvidia-*` CUDA packages
(two different pinned accelerator bindings in one environment — a clash the
platform explicitly rejects). You must deliberately choose the **CPU-only
binding**:

```
/app/venv/bin/pip install --no-cache-dir \
  --extra-index-url https://download.pytorch.org/whl/cpu \
  "torch==2.5.1+cpu"
/app/venv/bin/pip install --no-cache-dir \
  "onnxruntime==1.29.0" "onnx"
```

Then write `/app/dl-coexist.py`, an **executable** program that:

- imports torch (must be the `+cpu` build) and onnxruntime;
- asserts `torch.cuda.is_available() is False`;
- builds a small deterministic torch MLP
  `Linear(6,12) -> ReLU -> Linear(12,3)` with `torch.manual_seed(7)` and input
  `torch.randn(4,6)`, runs its **forward pass on CPU**;
- exports the same net to an ONNX graph (`onnx` is installed) and runs that
  graph in an onnxruntime CPU session on the same input;
- asserts `max|torch_out - onnx_out| <= 1e-3`;
- prints exactly one marker line
  `DL_COEXIST_OK torch=<torch_version> ort=<onnxruntime_version> maxdiff=<e>` to
  stdout and writes the **same line** to `/app/frameworks-ok.txt`.

CLI contract (the verifier re-runs the deliverable):

- no arguments → the default run above, exit 0;
- `--spec FILE` → read JSON `{"seed": int, "in": int, "hid": int, "out": int,
  "batch": int}`, all positive ints; run the same CPU forward pass for those
  dims, still print the `DL_COEXIST_OK` line and exit 0;
- a spec that is missing a key, has a non-int/non-positive value, or has
  `batch <= 0` → print one diagnostic to **stderr**, print **no** `DL_COEXIST_OK`
  line, exit **2**.

At the end of Task 3 `pip list` in `/app/venv` must contain **no** package
whose name starts with `nvidia` (no CUDA bindings) and a **single** `numpy`.

## Task 4 — serve the built package from a local package-index server

Make `/app/serve-index.sh` (executable) do the following, idempotently:

1. Build the swellkit wheel from the source tree into the package directory
   (rebuild each run is fine):
   `/app/venv/bin/pip wheel --no-deps --wheel-dir /app/package-dir /app/src`
   then move/stage the wheel so it also lives at
   `/app/package-dir/swellkit/swellkit-2.4.1-*.whl` (a per-project subdirectory).
2. Generate `/app/package-dir/index.html` (PEP-503 root): an HTML page that
   links to each project subdirectory, i.e. it must contain an `<a href="swellkit/">`
   anchor (plus optional other projects) so a client can discover `swellkit/`.
3. Generate `/app/package-dir/swellkit/index.html` listing an anchor per wheel
   file present in that directory (`<a href="swellkit-2.4.1-...whl">...`).
4. Serve the directory on **port 8765** bound to `127.0.0.1`:
   start a background `python3 -m http.server 8765 --bind 127.0.0.1
   --directory /app/package-dir`, write a pidfile at
   `/app/toolchain/../.serve.pid` (your choice of location) and if a stale
   instance already owns port 8765, kill it first so a re-run always leaves a
   **live** server on 8765. Wait until `curl -s http://127.0.0.1:8765/` succeeds.

Then run a real client install against the live server and capture it:

```
/app/venv/bin/pip install --no-cache-dir --target /tmp/hgclient --no-deps \
  --index-url http://127.0.0.1:8765 --trusted-host 127.0.0.1 "swellkit==2.4.1"
```

Redirect the command's combined output into `/app/client-install.log`, then
verify the artifact imports from the installed target
(`PYTHONPATH=/tmp/hgclient python3 -c "import swellkit; print(swellkit.__version__)"`
→ `2.4.1`) and append a final line
`CLIENT_INSTALL_OK version=2.4.1 index=http://127.0.0.1:8765` to
`client-install.log`.

The verifier kills any listener, re-runs `serve-index.sh`, asserts the server
is reachable on `127.0.0.1:8765`, cross-checks both generated HTML files
against the real wheel files, and performs its **own** scratch-venv
`pip install --index-url http://127.0.0.1:8765 ... swellkit==2.4.1` followed by
an import. `client-install.log` must contain the `CLIENT_INSTALL_OK` line.

## Hidden cases the verifier will exercise (documented here)

- `/tests/hidden/framework/` — edge API driving of the rebuilt framework:
  negative/empty/comment-only tables, zero amplitude, phase 180, malformed rows
  (arity, non-numeric, non-positive period → `ValueError`), RMS on empty/single/
  negative series, haversine zero-distance. Handle every one per the contract.
- `/tests/hidden/toolchain/` — wipe-and-reprovision the toolchain from scratch
  and compare live probes to the pinned strings.
- `/tests/hidden/dl/` — a tiny valid `--spec` that must succeed, and a malformed
  `--spec` that must exit 2 with no marker line.
- `/tests/hidden/server/` — restart the index server, validate the HTML against
  the staged wheels, unknown-project request must 404, fresh client install.

## Constraints

- Do **not** edit `/app/src/**`, `/app/kit/**`, `/app/data/**`,

- All deliverables must exist at the exact literal paths above; `dl-coexist.py`
