# Dusk-Forge — fit a sensor-calibration model under a 100 KB artifact budget

Dusk-Forge manufactures edge sensor nodes. You must train a calibration
model for the node's analog front-end and publish a deployable artifact.
The artifact directory will be flashed onto nodes with **100 KB of storage
reserved for the model — the entire `/app/model` directory, every file in
it, must total at most 102400 bytes.** An artifact over budget cannot be
flashed and fails the release gate.

Everything runs on CPU in this container. `numpy` is installed; there is no
GPU and no network access.

## Fixed inputs (read-only)

| Path                        | Contents                                                        |
|-----------------------------|-----------------------------------------------------------------|
| `/opt/forge/data/train.npz` | arrays `X` (4096 x 24 float32 features) and `y` (4096, target)  |
| `/opt/forge/data/eval.npz`  | same schema, 1024 held-out rows (use for validation)            |

The target is a smooth nonlinear calibration curve of the 24 channels
(generated by a fixed random process; per-channel gains and couplings
matter, most channels are near-noise). Do not modify the data files.

## Deliverables (both required)

1. `/app/predict.py` — a runnable loader/predictor with this interface:

   ```
   python3 /app/predict.py <model_dir> <input_npz> <output_npz>
   ```

   It must load the model artifact from `<model_dir>` (whatever files you
   put there), read array `X` from `<input_npz>`, and write a single array
   `pred` (shape `(n,)`, one prediction per input row) to `<output_npz>`.
   It must work on **any** input batch of 24-channel rows, including a
   single row. Use only the Python standard library and numpy. Do not
   hard-code dataset contents or expected outputs.

2. `/app/model/` — the serialized model artifact. Requirements:

   - The **total** size of the directory (sum over all files, recursive)
     must be **<= 102400 bytes**.
   - `/app/predict.py` must be able to reconstruct the model purely from
     what is in this directory.
   - Plan the layout accordingly: weights stored as float32 easily fit;
     training state (Adam/optimizer moments), per-epoch checkpoints,
     float64 copies, or duplicate serializations will **not**. The gate
     measures bytes, not intent.

## Quality gate

The deployed model is scored by root-mean-square error (RMSE) against the
true target on the shipped `eval.npz` **and on hidden calibration sets** you
have not seen (fresh draws from the same generator; one set has a slight
per-channel rescale). The release gate requires:

```
RMSE <= 0.45
```

on every calibration set. For calibration: always predicting the mean gives
RMSE ≈ 0.75 and the best purely linear model reaches only ≈ 0.52-0.60 —
the gate is deliberately placed so a genuinely nonlinear model is required.
A small MLP (e.g. 24 -> 160 -> 80 -> 1 with ReLU) trains to ≈ 0.3 with plain
numpy full-batch Adam in a few minutes; pick any architecture that fits the
budget and clears the gate with margin.

## Constraints

- Deterministic local compute only; no network at run or verify time.
- `predict.py` must not read `/opt/forge/data` at inference time — the
  hidden sets live elsewhere; all knowledge must come from `<model_dir>`.
- Keep `/opt/forge/data/*` unmodified.
