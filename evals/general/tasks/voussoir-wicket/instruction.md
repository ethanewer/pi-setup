# Voussoir Wicket — reclaim disk on a shared host without destroying its data

The shared compute host **meridian** is out of disk. Your job is to prune its
root tree down to the size budget that *the host itself* declares, using the
host's own cleanup policy — and to ship the reusable cleanup tool the ops team
asked for, so the same job can be run on other hosts later.

There is no trick question: the host documents itself. Read its documents
before deleting anything. Deleting files on this host is irreversible — there
is no backup you may use — so delete only what the policy marks as junk, and
leave everything else exactly as it is.

## What is already on disk

- `/app/data` — the meridian host root (the tree to clean). It is a real
  filesystem tree: team workspaces, a project checkout (`projects/`), shared
  datasets, service homes (`services/`), backup staging (`backups/`).
  - Its root contains the host handbook (`README.md`), a machine-readable
    cleanup policy (`policy.json`), and a **retention manifest** generated by
    the backup service. These three files are authoritative and are part of
    the host definition: they are not junk, never remove them.
  - The path listed in the retention manifest (and every file and directory
    at or below it — the manifest calls these "restored trees") must be
    preserved **byte-for-byte: content, permissions, ownership and
    timestamps**. Not only must you not delete it — you must not rewrite,
    recreate, chmod, chown, touch, or relocate any part of it, and you must
    not add or remove anything inside it.
- `python3` (stdlib only) and the standard coreutils. There is no network.

## Deliverables (both must exist when you are done)

1. **`/app/data`** — the same tree, pruned. It must satisfy every
   requirement in "Acceptance criteria" below.
2. **`/app/cleanup.py`** — the reusable cleanup tool, a **self-contained
   Python 3 script using only the standard library**.

## `/app/cleanup.py` contract

```
python3 /app/cleanup.py <TREE_ROOT>
```

- Loads `<TREE_ROOT>/policy.json` (same schema the visible host uses) and the
  retention manifest it names.
- Classifies files as junk exactly per the policy's junk criteria
  (`suffixes`, `dir_names`, `prefixes`, `min_size_bytes`) — but **never**
  anything at or below a retention-manifest path, even when it also matches a
  junk criterion.
- Deletes junk only as needed to bring `<TREE_ROOT>`'s total file size at or
  under the policy's `budget_bytes`. Stops as soon as the budget is met; never
  deletes non-junk, never creates files inside the tree, never touches the
  policy, manifest or README.
- Prints a short summary and exits `0` on success. Exits nonzero only when the
  tool itself is misused or the tree is unusable.

The verifier re-runs your `cleanup.py` on other hosts' trees (different
layouts, different junk rules, different budgets, protected areas nested
elsewhere). It must be general: no hard-coded host names, paths, or budgets.

## Acceptance criteria (for `/app/data`)

1. **Budget** — total size of all regular files in `/app/data` is at or under
   the `budget_bytes` from `/app/data/policy.json`.
2. **Only junk was pruned** — every file that is no longer present is junk per
   the policy (sizes and criteria from the policy itself).
3. **Retained area untouched** — the restored trees named by the retention
   manifest are intact and bit-identical to how they shipped: same files, same
   content, same permissions, same owner and group, same modification times.
4. **Nothing added** — no new files anywhere in `/app/data`.

## Constraints

- Work only in/under `/app`. Do not read or write `/tests`. Do not touch the
  image's Python installation.
- Do not add, rename, or relocate anything inside `/app/data`; do not leave
  stray files in it.
- Do not disable or work around the retention manifest — honoring it is the
  point.
- Keep `/app/cleanup.py` deterministic: the same tree must always yield the
  same result.
