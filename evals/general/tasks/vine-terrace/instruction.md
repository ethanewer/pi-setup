# Vine Terrace — a five-part scientific-analysis pipeline in one program

You are given a container whose working directory is `/app`. Installed Python
libraries include `numpy`, `networkx`, `jax`, `jaxlib`, `jaxley` (and its
`jaxley.channels` subpackage), and `pytest`. Your job is to author ONE Python
program, `/app/analyze.py`, that implements five independent data-analysis
competencies over the shipped fixtures, and then RUN it so it also writes the
two output deliverables described below.

The grader will invoke `/app/analyze.py`'s functions on the shipped (visible)
fixtures AND on fresh hidden inputs with the same formats. Everything must
generalize — do not hard-code the specific numbers from the visible fixtures.

## Deliverables

1. `/app/analyze.py` — a runnable Python module exposing the exact public API
   below.
2. `/app/primers.tsv` — generated by running your `analyze.py` on the shipped
   primer parts file (see Competency D).
3. `/app/adjust.json` — generated by running your `analyze.py` on the shipped
   causal graph (see Competency C).

Run `python3 /app/analyze.py` at the end so the two output files are produced.

## Competency A — bin point clouds into a normalized 2D histogram

Implement `points_to_histogram(points, box, bins)`:

- `points` is an (N, 2) array-like of `[x, y]` coordinates.
- `box` is `[xmin, xmax, ymin, ymax]`; `bins` is `(nx, ny)`.
- A point counts toward the grid only if `xmin <= x <= xmax AND
  ymin <= y <= ymax`. Both maximum edges are **inclusive** (a point exactly on
  `xmax` or `ymax` falls into the last bin).
- Return a 2D `numpy` array of shape `(ny, nx)` where `grid[i, j]` is the
  fraction of in-box points in cell `(j, i)` (i.e. divide the raw counts by the
  in-box total so the grid **sums to 1.0**).
- If no point is in the box, return an all-zero grid of shape `(ny, nx)`
  (its sum is 0, which is allowed for that empty case).

Visible fixture to test yourself: cloud at `/app/data/clusters.npy` with box
`/app/data/clusters_box.json`.

## Competency B — parse a non-standard delimited spectrum file

Implement `parse_spectrum(path)` → `(x, y)` where both are equal-length
`float64` numpy arrays.

The spectrum files use a **`;` field separator and a `,` decimal separator**
(e.g. `441,48` means `441.48`). The first two non-comment rows hold the
transposed columns: the abscissa row then the ordinate row. Lines whose first
non-whitespace character is `;` or `#` are comments and must be ignored, as are
blank lines. Strip whitespace from every field. Raise `ValueError` if a field
is empty, if fewer than two data rows exist, or if the two rows have unequal
length.

Visible fixture: `/app/spectrum/run471.spect`. A hidden file with more columns
will be supplied.

## Competency C — parse a causal graph and derive all minimal adjustment sets

Implement `minimal_adjustment_sets(graph_path)` → a list of adjustment sets,
each set a sorted list of node-name strings, ordered by `(len, lexicographic)`.

The graph file format is plain text:

- `# ...` lines are comments and ignored.
- `u1 -> x` lines declare a directed edge from the left node to the right node.
- A line `effect: x -> y` names the causal effect: the left node is the
  treatment `x`, the right node is the outcome `y`.
- An optional line `forbid: n1, n2` names nodes that may never be part of an
  adjustment set.
- Blank lines are ignored. Node names are single tokens (letters/digits, no
  spaces).

Return **all inclusion-minimal adjustment sets** satisfying the back-door
criterion for `effect x -> y`:

- No set may contain the treatment or outcome, any node listed after
  `forbid:`, or any **descendant of the treatment** `x`.
- A candidate set must **block every back-door path** from `x` to `y` (every
  path starting with an edge directed into `x`). Use the standard moral-graph
  d-separation criterion on the graph with `x`'s outgoing edges removed.
- A set is *inclusion-minimal* if no proper subset of it is also a valid
  back-door adjustment set.

Visible fixture: `/app/causal/graphA.txt` (expected output: `[["u1", "u2"]]`).
A hidden graph with a `forbid:` line will be supplied. Use any graph/back-door
implementation you like (e.g. `networkx` or your own d-separation routine) —
only the returned list matters.

## Competency D — design restriction-assembly (golden-gate) primer oligos

Design forward and reverse primers for every part in a TSV. Implement
`design_primers(parts_tsv_path)` returning a list of dicts, one per primer
(two dicts per part: `<part>_F` and `<part>_R`), in `_F, _R` order for each
part preserving the file's part order.

Input TSV columns (tab-separated, header on row 1):
`part  prefixF  prefixR  site  junction  anneal_min  anneal_max  tm_min  tm_max  flank5_30nt  flank3_30nt`

Design rules (constants shared with the grader):

- Melting temperature uses the Wallace rule on the **3' annealing window** only:
  `Tm = 2*(#A + #T) + 4*(#G + #C)`.
- **Forward primer** = `prefixF + site + junction + last-L bases of flank5_30nt`.
- **Reverse primer** =
  `prefixR + reverse_complement(site) + reverse_complement(junction)
   + reverse_complement(first-L bases of flank3_30nt)`.
- Choose the **smallest integer** annealing length `L` in
  `[anneal_min, anneal_max]` such that the Tm of that annealing window is in
  `[tm_min, tm_max]` (inclusive). Every part's flanks are constructed so that
  such an `L` exists.
- Write each dict with keys:
  `name, seq, anneal_len, tm, site, junction` where `site`/`junction` are the
  (reverse-complemented, for reverse primers) forms placed in the primer, and
  `tm` is the raw Wallace Tm of the chosen annealing window.

Then, in your `__main__` run, also serialize the primers designed from the
shipped file `/app/primer/parts.tsv` to `/app/primers.tsv` with this exact
tab-separated header and one row per primer (forward then reverse, in part
order):

```
name	primer5to3	overhang_5	anneal_len	tm_anneal	site	junction
```

where `primer5to3` is the full designed sequence, `overhang_5` is the number of
5' bases before the annealing window (`len(seq) - anneal_len`), `tm_anneal` is
the Tm formatted to one decimal place (e.g. `60.0`), and `site`/`junction` are
the (reverse-complemented where appropriate) forms. The grader compares this
file to a reference byte-for-byte (after trailing-newline normalization) and
also re-runs `design_primers` on a hidden parts file, so the exact row order,
headers, and fields matter.

## Competency E — translate neuron biophysics channel mechanisms into jaxley

The shipped NEURON-style mechanism file `/app/biophys/rgc.mod` specifies three
ion channels for a compact retinal-ganglion-cell model:

- a fast Na+ channel (`jnaf`): current `gmax * m^3 * h * (v - ena)`;
- a delayed-rectifier K+ channel (`jkd`): current `gmax * n^4 * (v - ek)`;
- a passive leak (`jleak`): current `gleak * (v - eleak)`.

Port these into three `jaxley.channels.Channel` subclasses (e.g. `NaF`, `Kd`,
`Leak`) using the exact rate functions and initial conditions in `rgc.mod`, and
provide a conversion class:

```python
class RGCChannels:
    def __init__(self, params: dict): self.params = params
    def add_channels(self, cell): ...   # inserts the three channel classes
```

`params` is a dict read from a JSON file with keys like `g_na`, `e_na`,
`g_k`, `e_k`, `g_leak`, `e_leak`, `stim_nA`, `t_ms`, `delta_t`.

Implement `membrane_response(swc_path, params_path) -> np.ndarray` that:

1. loads the SWC morphology with `jaxley.read_swc(swc_path, ncomp=1)`,
2. attaches the three RGC channels via `RGCChannels(params).add_channels(cell)`,
3. builds a `jaxley.Network` of that cell,
4. stimulates with an injected current: `stim_nA` nA during the window
   `2.0 ms <= t < 22.0 ms`, else 0, on a time grid `np.arange(0, t_ms, delta_t)`,
5. records the membrane potential `v` and integrates with
   `jaxley.integrate(net, t_max=t_ms, delta_t=delta_t)`,
6. returns the resulting voltage array with shape `(n_compartment, n_steps)`.

The grader will call `membrane_response` on a hidden SWC + params pair and
compare the full voltage trace to a reference within a tight tolerance, so the
channel kinetics (rates, exponents `m^3 h`, `n^4`, reversals, gating time
constants) must match `rgc.mod` exactly. Draft a voltage `v` yourself by
stepping `v' = -(sum of ionic currents)` with the given parameters.

Visible fixtures for self-testing: `/app/biophys/morph_visible.swc` and
`/app/biophys/params_visible.json`.
