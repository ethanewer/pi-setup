SUBKEY-SEED CONSTRAINT / SHA-1 DIGEST
=====================================

Each passphrase candidate C (a string such as "morn-358") is the seed for a
SHA-1 "subkey" derivation with one important constraint: the seed is the
candidate itself — there is no salt, no pepper, no key-derivation function, and
no HMAC. The subkey is computed only from the UTF-8 bytes of C.

Concretely, for every candidate C the fleet subkey is:

    subkey(C) = SHA-1( UTF-8 bytes of C )

rendered as the usual 40-character lowercase hexadecimal text string.

Because the seed equals the candidate and there is no iteration or salt,
computing this digest for all 900 candidates finishes essentially instantly on
CPU.

Feed the subkey into the structural rule in /app/recovery/hash-rule.txt to
reduce the full candidate space down to a tiny shortlist.
