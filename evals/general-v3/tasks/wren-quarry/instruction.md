# Wren Quarry — apply per-line defect repairs through the fix service

The `rectify.py` module of the Wren Quarry feed-ingestion pipeline has five
single-line defects. The defect report is only available over HTTP from the
**defect-service**, and every repair must be applied **through the service's
fix endpoint** — the service allows only a small fix budget, and the grader
fails the run if too many fix attempts were spent. Direct editing of the
target file is detected and rejected.

## Environment

- Working directory: `/app`. Python 3.12 is available (`python3`). No network
  beyond localhost.
- `/app/pipeline/rectify.py` — the defective module. **Do not edit this file
  directly**; the only sanctioned way to change it is the fix endpoint.
- `/app/pipeline/examples.json` — visible sanity cases showing the expected
  behaviour **after** all defects are repaired.
- `/app/ops/defect_server.py` — the defect-service (read-only; do not modify).
  Start it with:
  ```
  python3 /app/ops/defect_server.py --port 8710
  ```
  (run it in the background; it binds `127.0.0.1:8710` and persists all state
  to `/app/ops/state.json`).

## The fix budget

- The service grants **8 fix attempts**. `POST /fix` always consumes one
  attempt — successful or not, including malformed requests or repeats of a
  line you already fixed.
- The grader additionally requires **no more than 6 attempts spent** in total.
  With 5 defects that leaves room for at most one mistake: read the report,
  decide each replacement carefully, and send one well-aimed request per
  defect line.
- Once the budget is spent the service locks up (HTTP 409) and no further
  fixes are possible.

## Service API (127.0.0.1:8710)

- `GET /defects` →
  `{"file", "budget", "fixes_used", "remaining", "locked", "defects":
  [{"id", "line", "kind", "current", "expected"}, ...]}`.
  Each defect entry gives the 1-based `line` number, the *current* (defective)
  line text, and an `expected` description of the intended semantics.
- `POST /fix` with JSON body `{"line": <1-based int>, "content": "<full
  replacement line>"}` → replaces that entire line of `/app/pipeline/
  rectify.py` with `content` (keep the correct indentation!) and returns
  `{"ok", "applied", "fixes_used", "budget", "remaining", "locked"}`.
- `GET /status` → current attempt count, applied fixes, and file hashes.

## Deliverables (both required)

1. **`/app/pipeline/rectify.py`** — the module with every defect repaired via
   the fix service, satisfying its docstring contracts and the visible
   examples. The grader imports it and runs it on fresh hidden cases.
2. **`/app/ops/state.json`** — the service's persisted record of the applied
   fixes (created by the service itself; it must show every defect line
   repaired within the attempt limit, and the final file hash must match the
   on-disk file).

## Repairs the grader expects

Each defect is a one-line bug whose fix restores the documented contract:

- `running_total`: each value must be **added** to the running accumulator.
- `moving_average`: the loop must yield **all** full windows
  (`len(values) - window + 1` means).
- `clip_values`: clamp with `min(max(v, lo), hi)` into `[lo, hi]`.
- `chunked`: chunk starts must advance by exactly `n`.
- `top_k`: return the **k largest** values in **descending** order.

## Hidden probes

The grader rebuilds nothing; it (a) executes `/app/pipeline/rectify.py` on
hidden cases covering empty lists, full-window boundaries, `window > len`,
`k <= 0`, `k > len`, short final chunks, negatives and floats, and raises of
`ValueError`, and (b) audits `/app/ops/state.json` for the attempt budget,
that every defect line was repaired, and that the file was only ever changed
through the fix service (pristine hash chain).

## Constraints

- Do not modify `/app/ops/defect_server.py` or `/app/pipeline/examples.json`.
- Do not edit `/app/pipeline/rectify.py` with an editor, `sed`, a script, or
  any other channel besides `POST /fix`.
- If you restart the service, keep the default `--state /app/ops/state.json`
  so the attempt history is preserved.
